## 1. 背景与目标

我要用这个项目参加传智杯「AI WEB 网页开发挑战赛」，截止 2026-11-18。我当时不知道自己的项目离评分表还差什么，所以第一步不是写代码，而是把赛道详情页丢给 AI 做一次差距分析，再决定做什么。核心缺口后来确认是评分权重最高的两块：**Agent 工具化（Function Calling，12%）** 和 **RAG（6%）**——这两块我当时完全没做。

## 3. AI 的方案与关键决策

AI 先从赛道页的 JS 包里挖出真实接口拉到完整赛题（页面是 Nuxt SPA 直接抓不到内容），然后逐项对照评分表给出 6 项缺口清单。我同意了它对第 1、2、5 项的方案，并用第 2 轮 Prompt 明确排除了材料写作（3）、部署稳定性（4）、报名事务（6）——这三件是我自己要做的事，不值得花 AI 的时间。

AI 的几个关键架构决策（我全部采纳）：

- **Function Calling 而不是 MCP**：评分标准两者任选其一，做 Function Calling 工作量小、且能把已有能力（教学知识库、歌词曲库、生词本）直接拆成模型可自主调用的工具
- **工具循环设上限 3 轮**：防模型陷入循环；轮次用尽强制摘掉工具要正文，避免极端情况下返回空串
- **意图门控**：只在命中学习意图（语法/发音/生词/歌词/TOPIK）时才挂工具，纯闲聊和时效新闻走原链路，控制免费档延迟
- **多层失败降级**：模型/网关不支持 function calling 时自动摘除工具降级，任何一层失败都不影响对话可用
- **RAG 不上向量数据库**：智谱 embedding-3 + 本地 JSON 索引缓存 + 余弦相似度；**向量检索失败自动降级关键词检索**

## 4. 问题与引导修复 ⭐（评分核心）

这一轮的问题大多出现在**真实 API 冒烟验证**阶段，AI 在验证中自检发现、当场修复，我负责圈范围和验收：

1. **曲库检索匹配不到歌手**：冒烟时韩文「아이유」匹配不到，定位是曲库 `artist` 字段只写了中文别名「IU」。AI 的修法值得学习：**复用 `song-library.js` 里现成的韩中别名正则并导出**，而不是在工具里重复写一份——避免两处规则漂移
2. **回归测试红了**：现有测试只 mock 了 `chatJSON`，而新入口是 `chatJSONWithTools`。修 mock、保留原断言意图，不是改测试迁就实现
3. **embedding 单次最多 64 条**：82 条语料分批建索引
4. **embedding 账户余额不足、向量索引建不成**：这正是「关键词降级」设计的价值时刻——RAG 检索和工具链路照常工作在关键词模式，将来充值后重启自动补建索引。**降级不是摆设，是真的被用过**
5. **端到端验证持续 429 限流**（与正式服务共用免费 Key）：以此前直连冒烟的成功结果为准，趁等待补了一个边界修复（工具轮次用尽强制要正文）

我在这条链里的引导作用主要是第 2 轮 Prompt：**用「除 3、4、6」一句话把 25 天倒排期的优先级交给 AI 执行**，避免它擅自去写文档或动部署。
