# 链 2 · 翻译守卫自愈重试（对应提交 `1680ebd`）

- **日期/工具**：2026-10-24 上午 · ZCode CLI（GLM 大模型驱动的编码 Agent）

## 1. 背景与目标

系统里有一个「未翻译韩语兜底」守卫：如果 AI 回复里的韩语段没有配上中文翻译，就用安全话术替换整条回复，防止出现用户看不懂的裸韩语。当时刚升级完「全方位老师」提示词并重启服务，我在网页上随手测了一句话，结果**最简单的「再见」都答不上来**——只返回一句模板化的道歉。这说明守卫在误杀正常回复，必须修。

## 2. 我的 Prompt 原文

**第 1 轮（打开网站自测，发现现象）：**

> 「打开网站」

**第 2 轮（一句现象描述的 Bug 报告）：**

> 「为什么最简单的再见为什么回答不上来」

（附聊天界面截图：AI 对「再见」只回了模板安全话术）

## 3. AI 的方案与关键决策

AI 从截图现象先给出假设（「未翻译韩语兜底」拦截器把整条回复替换了），然后走了一条很规范的定位路径：

1. 找到守卫逻辑：`isSevereUntranslated` 判定「韩语段后一行没有中文」为违规，达到阈值（长度 ≥12 字或韩语行 ≥3）就整条替换成道歉话术
2. **写临时脚本按流式路径复现，连跑 3 次**——3 次全新会话都没触发，说明问题与会话上下文有关
3. 复测带历史上下文的场景：上一轮在教英语「butter you up」时，模型更容易输出「韩语 + 罗马音、翻译不另起一行」的格式，被守卫判为违规——**守卫的判定标准太死板，误杀了格式合规但排版不同的正常回复**

修复方案的决策：不是简单放宽阈值（那会漏掉真正的漏翻译），而是**把「道歉降级」改成「自愈重试」——守卫触发时带纠正提示自动重试一次，重试成功就把好答案换回去，只有重试也失败才道歉**。这样既保住守卫的安全兜底，又不牺牲正常回复。

## 4. 问题与引导修复 ⭐（评分核心）

这条链的引导核心是第 2 轮 Prompt 本身：**只描述现象（「最简单的再见答不上来」），不预设原因**。这给了 AI 两条关键自由度：

- 它没有直接改守卫阈值了事，而是先用脚本复现证明「新会话不复现」——如果我当时猜一个原因（比如「提示词坏了」），它很可能顺着我的猜测走错方向
- 复现失败本身成为线索，把定位收敛到「上下文相关的格式误判」，最终修复才落在正确的层面（重试自愈，而不是放宽或删守卫）

实现中 AI 还确认了两个前提再动手：流式 `chatStream` 的 `onDelta` 可选（不破坏流式体验）、`security.checkText` 未配置微信审核时本地放行（测试可 stub）。随后补了**两条路径的回归测试**：第一次输出没翻译 → 重试成功；重试也失败 → 才道歉。

## 5. 结果验证

- 回归测试 **17/17 全绿**（新增 `translation-guard.test.js`，71 行）
- 删掉调试脚本，用和 Bug 截图**完全相同的场景**做端到端验证：先聊英语再问「再见」，流式接口返回完整双语回答，道歉话术不再出现
- 落定为提交 `1680ebd`（agent.js 守卫重试逻辑 + 新测试文件）

## 6. 沉淀

**报 Bug 时给「最小现象 + 截图」而不是给猜测的原因——AI 用「能否复现」代替「听谁解释」，定位路径会自己收敛到正确层面。**
